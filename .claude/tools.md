# SVGedit User-Facing Tools

> **How to use this doc:** Look up tools by panel location (the full list of command ids, labels and keys is the generated [`commands.md`](commands.md), the authority for keys; these tables do not repeat the keys). Each entry gives the element ID, what the control does and what is not obvious about it; the how is in the code headers (`file-map.md`). Extension-provided tools are in a separate section at the bottom.

## Left Panel — Drawing Tools (`src/editor/panels/LeftPanel.html`)

The left panel is a vertical column of tool buttons. Some are "flying buttons" (`se-flying-button`) with several variants in a flyout.

| ID | Tool | Notes |
|----|------|-------|
| `tool_select` | Select / pointer | Select, move, resize. With 2+ selected, one union box with 8 grips (rotate grip hidden) applies a **uniform group scale** about the opposite corner / edge (`select.js` `showGroupSelector`, `event.js` `resizeGroup`). Shift+drag locks the dominant axis; Shift+drag the rotate grip snaps to 15°. **Alt+drag a resize grip** of a group or a multi-selection **stretches its middle and keeps its ends** (`core/stretch.ts`, `svgCanvas.stretch`): per dragged axis the selection is sliced at its middle line; a part wholly on the grip's side moves with it, one on the other side stays, one across the middle stretches from its fixed edge (a group across it is opened and sliced inside). The group's own transform is untouched; each part is baked like a resize (`applyAffines`, strokes keep their width); one undo step. Alt is read at the first movement. No touch equivalent yet. A click on stacked shapes **prefers an already-selected one** over the topmost. The move cursor shows wherever a press would move something (`svgCanvas.setCursorHint('move')`, `toolCursors.ts`). |
| `tool_fhpath` | Freehand pencil | Pointer coordinates pass through an EMA low-pass filter (`pencilStabilization`, 0–1, default 0.3) to damp tremor. On commit the points are fitted to cubics by the corner-keeping fit (`core/path-fit.js`, `core/path-simplify.js`): a turn sharper than ~100° stays an exact corner, the rest becomes as few cubics as stay within `pencilFidelity` (user units, default 2). `pencilSimplify: false` restores the legacy smoothing. Both settings are in Editor Preferences. **Continue:** a stroke that starts within 6 screen px of an end of the one selected single-subpath open `<path>` extends it (one `Continue path` undo step; Alt = new path; ending near the other end closes it; `core/pen-continue.js`). |
| `tool_brush` | Custom brush | Variable-width freehand brush (nib roundness, thickness, angle, taper, opacity, smoothness, up to 5 presets) set in the tool's options bar (top panel, while the brush is active): the five slots as a button row (click loads, an empty slot saves the live brush, double-click renames; the brush in use is solid, a loaded slot edited since is dashed with a **Save** button that writes the edits back, **✕** clears the slot), then Size and Opacity and a **More** toggle for Smooth, Angle, Round and the two tapers (`ext-brush/brushOptions.ts`). Pen pressure modulates thickness; mouse and touch draw at constant width. Renders a filled `<path>` outline (`core/brush-stroke.js`); provided by `ext-brush`. |
| `tool_line` | Line / arrow | A straight two-point `<line>`. Releasing an endpoint over (or within ~12 px of) a shape **binds** it: it snaps to the shape's edge and follows the shape as it moves or resizes; **Alt** keeps it free. Binding is `ext-connector`; arrowheads come from the markers panel (`ext-markers`). |
| `tool_path` | Bezier path | Point-by-point path. A click on the first point closes it (with 3+ points, or 2 along a curved closing edge); a click on any other placed point finishes it open (so a straight two-point path stays a line). **Continue / join** (`core/pen-continue.js`): **with Shift held**, pressing within 6 screen px of an end of an open single-subpath `<path>` in the current layer or entered group (its own `transform` is kept; the gesture works in the layer's space) carries that path on (one `Continue path` step); pressing another such end while drawing joins the two (`Join paths`; the carried-on path survives). A `pen_end_hint` ring marks an end a Shift-press would use (shown only while Shift is held); a plain press on an end starts a new path, so two shapes can share a vertex and stay distinct. Paths with `se:taper-d` / `se:orig-d` / `se:fx-d`, closed and multi-subpath paths are never offered. |
| `tools_shapes` *(flying)* | Shapes (Rect / Ellipse / Star / Polygon …) | Combined flyout with a **fixed trigger icon** (`shapes.svg`; `se-flyingbutton`'s static-icon `src` mode) that does not follow the last-picked variant. Only the primary variant of each shape is here (square, circle, free-hand rect / ellipse are reachable through `svgCanvas.setMode`, not the UI). `tool_rect` (R) and `tool_ellipse` (E) are built in `LeftPanel.html`; the extensions append their tools into this same host at runtime. A key re-arms the last-picked shape. |
| `tool_text` | Text | Add / edit text. **Multiline:** the edit buffer `#text` is a `<textarea>`; **Shift+Enter** adds a row, **Enter** commits. SVG has no newline, so each row is a `<tspan>` with a shared `x` and `y` stepped by `font-size × 1.2` (`setMultilineText` / `getTextWithNewlines`, `core/dom-utils.js`; every `#text` read and write goes through them). The caret engine (`core/text-actions.js`) indexes `#chardata` by textarea caret position and is row-aware. **Area text:** a drag of ≥ 5 screen px draws a box and wraps the text to it (`se:wrap-width` / `se:wrap-height` / `se:valign`, soft rows are tspans with `se:soft`; `core/text-rows.js`, `core/text-wrap.ts`); its grips resize the box and re-wrap live, and ArrowUp / Down / Home / End move by drawn row. |
| `tool_image` | Image | Opens the **Insert image** dialog (`se-image-import-dialog`): file upload, URL, or **Import from vault** (only when the host provides `window.svgEditHost.pickVaultImage`; see `architecture.md` › Host bridge). An SVG file, or an unlocked vault drawing, imports as editable shapes through `insertSvgElements` (several elements are wrapped in one `<g>`); **Import as editable paths** (off by default) also turns basic shapes into `<path>`. Anything else is embedded as an `<image>` by `insertImageFromHref` (`dialogs/insertImage.ts`), stamping `data-vault-link` / `data-vault-locked`. Flow: `LeftPanel.clickImage` → dialog → `handleImageImport`. |

**Lock mode.** A tool normally reverts to Select after one object. **Double-click** a drawing tool (or **Shift+Enter** while it is focused) *locks* it for drawing many objects; switching tools exits it. A locked tool shows an accent outline ring (`.locked` in `seButton.ts` / `seFlyingButton.ts`). Lockable: `tool_fhpath`, `tool_line`, `tool_path`, `tool_text` and the shapes flyout (the dblclick binds on the flyout host and locks the active variant). State is `svgCanvas.getToolLocked()` / `setToolLocked()`; `LeftPanel.lockTool` sets it and `updateLeftPanel` clears it on a tool switch. The reset is gated in `event.js` `mouseUpEvent` and in `text-actions.js` `toSelectMode`. An unlocked path switches straight to Select with the new path selected (click it again to edit nodes); `event.js` hides the in-progress node grips first (`getPath_(element).show(false)`) because that switch bypasses `pathActions.toEditMode()`.

**Extensions add** (details in the sections below and in `extensions.md`):
- `tool_shapelib` (ext-shapes); `tool_star` / `tool_polygon` (ext-polystar) and `tool_spiral` / `tool_arc` / `tool_rectgrid` / `tool_polargrid` (ext-shape-family) go into the `tools_shapes` flyout.
- `tool_shaper` (ext-shaper, Shift+N), `tool_smooth` (ext-smooth-tool): rough strokes become shapes; brushing smooths part of a path.
- Brush section (Design tab, ext-art-brush): `brush_new_art`, `brush_new_pattern`, `brush_delete`, `brush_edit_path`, `brush_expand`, `brush_release`, the picker `#ext-art-brush-pick`.
- `tool_blend` (ext-blend): click one shape, then another. The first tool with an options bar (`#tool_options_panel`, drawn from `options()`). Blend section (Design tab): `blend_make`, `blend_expand`, `blend_release`, `blend_replace_spine`, `blend_reverse_spine`, `blend_align_path` (toggle), `blend_detach_spine`.
- `tool_width` (ext-width-tool): drag outward from a stroke to add a width point, drag a diamond to slide it, Delete removes it.
- `tool_distort` (ext-distort-tool): drag a corner of the selection's box to distort it (a live effect); Shift keeps one axis; Free / Perspective on the options bar.
- `tool_gradient` (ext-gradient-tool): edit the selection's linear / radial gradient on the canvas; Fill / Stroke and New (Linear / Radial) on the options bar. Press-and-drag on a shape whose chosen paint is a plain colour (or none) makes a linear gradient along the drag, or a radial one centred on the press with the drag as its radius (its colour fading to white, black for a light colour, white to black for none), a click makes the default left-to-right one (a radial one filling the box); one undo step.
- `tool_corners` (ext-corner-tool): a widget in each corner: drag to round (all corners, or the picked ones), Alt-click cycles round / inverted / chamfer, click or Shift-click picks; Radius, Kind and Pick several on the options bar. The Design-tab Corners panel (ext-corner-radius) still edits every corner.
- `tool_recolor` (ext-recolor; command in group Edit, button in the Effects tab): opens `se-recolor-dialog` for the selection.
- `tool_wand` (ext-magic-wand): click a shape to select every shape sharing its fill / stroke / both / stroke weight / opacity / type (colour tolerance); Shift adds, Alt subtracts, empty canvas clears; Match, Click (for touch) and Tolerance on the options bar. Records no undo step.
- `tool_measure` (ext-measure): drag between two points to read distance, angle, Δx, Δy in the base unit (Shift = 45°, or the *45° steps* option for touch). Changes nothing.
- `tool_transform_each` / `tool_split_grid` (ext-layout-ops; Layout section at the end of the Design tab, with a selection): `se-params-dialog` with a live preview.
- `tool_cutter` (ext-cutter, C), `tool_curvature` (ext-curvature, Y), `tool_puppet_warp` (ext-puppet-warp, X; icon `pin.svg`).
- `tool_eyedropper` (ext-eyedropper): click an element to sample its **fill** (only the fill), then pick from a menu at the click point: set as fill / outline / background colour, **Apply style to selection** / **Apply selection's style to this** (greyed out unless another shape is selected), or **Generate matching palette** (`<se-palette-dialog>`: eight OKLCH colours, one per hue, optimised against the sampled colour; the purpose dropdown reweights the optimiser; algorithm in `src/editor/palette/`). Escape returns to Select.
  **Copy style** (`styleCopy.ts` `copyStyle(editor, source, targets)`, one `transact`): fill, stroke, stroke-width, dasharray, linecap / linejoin / miterlimit, opacity, fill- / stroke-opacity, fill-rule, paint-order (an attribute the source lacks is *removed* from the target) and, text → text only, font family / size / weight / style. A gradient or pattern fill is shared **by reference**; drop shadow, outline, glow and feather are rebuilt per target through `shadowApi` / `outlineApi` / `glowApi` (own `<filter>`, removed when the source has none); markers are cloned per target (`mkr_<pos>_<targetId>`, so recolouring one never recolours another; only line / polyline / polygon / path take markers, `<line>` no mid marker). A group source contributes its first shape; a group target restyles the shapes inside it. A **tapered** source is read through `se:taper-style`; a tapered *target* is skipped. The Blur slider, geometry and live-effect state are not copied.
- `ext-panning`: the Pan / hand tool, after Select.

**No Zoom tool button.** `tool_zoom` has no toolbar entry; the `'zoom'` draw mode and `core/event-zoom.js` are still reachable programmatically. Zoom with the top-panel `<se-zoom>` dropdown (25–1000 % plus Fit variants) or Ctrl+wheel.

**Drag-to-reorder and the "Additional tools" bucket.** Every direct child of `#tools_left` (a tool button or a whole flyout, never a sub-variant) can be dragged to reorder, or onto the **Additional tools** bucket (`<se-tool-overflow id="tools_overflow">`, always last) to tuck it away; dragging it back restores it. A tucked tool keeps its click handler, hotkey and lock gesture; only its location moves. It is also keyboard-operable: `#tools_left` is an ARIA `toolbar` with a roving tabindex (Arrow keys, extending into the open popover); **Space** grabs the focused tool, Arrows swap it with a neighbour or cross into the other zone, Space drops it, **Escape** restores the order from the grab; **Enter** clicks the focused tool; **Shift+Enter** locks it (wired in `LeftPanel.finalizeToolOrder()` *after* `toolDragReorder.ts`'s keydown listener, so the plain-Enter click runs first, as a mouse double-click's two clicks precede its `dblclick`). A live region announces grabs, moves and drops. Order and bucket membership persist via `toolOrder.ts` (`userDataAdapter.getToolOrder` / `setToolOrder`, else `localStorage` `svg-edit-tool-order`), reconciled on each load (`reconcileToolOrder`: stale ids drop, new ids join the main row). In a pane too short for the column, `toolAutoFold.ts` folds the last main tools into the drawer (`data-auto-folded`; `withoutFold` keeps that out of the saved order; a tool the user drags out is theirs again). Built once, after every extension has added its button, by `LeftPanel.finalizeToolOrder()` on the canvas `extensions_added` event; the mechanics are in `toolDragReorder.ts`.

**Shortcut badges.** A tool in the left column, and a button of the top panel (frame `U`, wireframe `F`, clone `D`, undo `⌘Z`…), shows its key at the bottom right of its icon (`V`, `⇧N`, `⌘I`); one without a key shows nothing (`EditorStartup` starts `initToolShortcutBadges` for `#tools_left` and for `#tools_top`). `toolShortcutBadges.ts` writes `data-shortcut` from the hotkey manager's **effective** first key, so rebinding shows at once (`HotkeyManager.onChange`); a MutationObserver picks up late tools and a flyout's changed last-picked tool. The Shapes flyout, with no key of its own, shows the key of the tool its face activates. The badge is CSS `::after` on the host (`svgedit.css`) and is hidden in tablet mode. A new tool gets one simply by having a key.

**Tooltips.** `tooltips.ts` replaces the browser's slow, unreliable `title` tooltip: while the pointer rests on any element (shadow DOM included) that has a `title`, the text is held back and shown in one `.se-tooltip` bubble (top layer, mounted in `.svg_editor`) after ~350 ms, or ~40 ms when moving between neighbours; the `title` returns on leave. Components keep authoring a plain `title`. A disabled `se-button` stays hit-testable so its tooltip shows why it is unavailable. The *Additional tools* drawer (`se-tool-overflow`) caps its height to the window and scrolls.

## Adding or changing a toolbar control

A toolbar / menu action is a **command** (`editor.commands`, `commands.js`): register it with a stable id and point the button at it with `command="<id>"`. The hotkey, the favorites menu, the tablet shell and the host API then share one implementation, and the button's `disabled` state follows the command's `enabled` check (`refreshEnablement`). Buttons without `command=` still work through the transitional adapter. See `coreCommands.ts`, `panelCommands.ts` and `extensions.md` › Commands.

## Top Panel — Quick Actions (`src/editor/panels/TopPanel.html`)

A horizontal flex bar of rounded **trays** (shared `.quick_tray` style) that holds only selection-agnostic *quick actions*; shape attributes, text styling, stroke and combine ops live in the Right Side Panel tabs. `TopPanel.ts` `updateContextPanel` shows and hides trays by class.

> Layout: title (left) → view tray → `#theme_panel` → `.path_node_panel` → `#tool_options_panel` → object / arrange trays → `#top_end` (the sticky right cluster: `#history_panel` Undo / Redo + `#zoom_panel`, so Undo / Redo never move when trays appear).

### Arrange / z-order dropdown (`tool_arrange` / `tool_arrange_multi`)

An `se-list` with a **fixed** trigger icon (`move_top.svg`; static-icon mode, set by `src` on the `<se-list>`), one copy per tray; both dispatch `change` to `TopPanel.clickArrange`:

| Item | Action | Canvas call |
|------|--------|-------------|
| `front` | Bring to Front | `moveToTopSelectedElement()` |
| `forward` | Bring Forward | `moveUpDownSelected('Up')` |
| `backward` | Send Backward | `moveUpDownSelected('Down')` |
| `back` | Send to Back | `moveToBottomSelectedElement()` |
| `switch` *(`arrange_switch`, multi list only)* | Switch Layers (swap the z-order of 2) | `switchSelectedZorder()` |

`arrange_switch` shows only when **exactly two** elements are selected. The other items act on **every** selected element and keep their relative stacking order (a multi-selection moves to the top as a block); a selected `<g>` moves as one unit. `selected-elem.js` groups the elements by parent and records one batched undo step.

### Align dropdowns

`tool_align_multi` is an `se-list` (fixed `align.svg` face) with items `l/c/r/t/m/b/dh/dv`: `TopPanel.clickAlignMulti` → `clickAlign` → `alignSelectedElements(value, tool_align_relative.value)`; single-element `tool_position` is the align-to-page analogue. `tool_align_relative` is an `se-list` (fixed `relative_to.svg` face) with text-only `se-list-item`s (`option="tools.*"`, no `src`) and `track-selection`, which keeps the last-picked item highlighted although the face stays fixed.

### Image actions (`.image_panel` tray, one `<image>` selected)

`tool_image_crop` (no key) is shown only when `svgCanvas.imageCrop.isEligible(elem)` (`core/image-crop.js`): a plain `<image>` that is **not** vault-linked (`data-vault-link`) and **not** transformed (the crop overlay is axis-aligned). It calls `svgCanvas.startImageCrop(elem)`: a dashed crop rect with 8 handles of its own (not the `SelectorManager` grips), freeform, clamped to the image's current bounds. While cropping, `tool_image_crop_apply` / `_cancel` appear in the same tray with the class `.imagecrop_panel`, so their visibility follows the mode (`TopPanel.toggleImageCropMode` from `EditorStartup.modeListener`), not the selection. **Apply** (`svgCanvas.applyImageCrop()`, async) is **destructive**: it resamples the cropped region into a new bitmap (display coordinates mapped to the natural pixel size), re-encodes it (the original `data:` MIME type when sniffable, else PNG) and rewrites `href` / `x` / `y` / `width` / `height` in one undo step, so a later **Convert to editable SVG** (`tool_trace_image`) traces less data. A CORS / tainted-canvas failure rejects, is shown by `seAlert` (`TopPanel.applyImageCrop`) and leaves the session open. Image loading is shared with `traceImage.ts` (`core/load-image.js`).

### Join paths (ext-path-edit, select mode)

`svgCanvas.joinSelectedPaths()` (`core/path-join.js`; geometry `joinSubpaths` in `core/path-edit.js`; eligibility `canJoinPaths(elems)`): one open plain path is **closed** (`tool_join_paths`, Object → Path); two plain paths in the same parent are **joined** (`tool_join_paths_multi`, Combine row). Endpoints within 0.5 user units (÷ zoom) merge into one anchor, otherwise a straight segment connects the nearest ends (reversing as needed). The lower element keeps its id and style, the upper is removed, in one `BatchCommand`; the second path is brought into the first's coordinate system when transforms differ. Not offered for closed paths, shapes, live-geometry paths (`se:fx-d` / `se:orig-d` / `se:taper-d`) or paths in different parents. Registry-only commands in group `Path`: `path_join`, `path_average_h/v/both`, `path_add_anchors` (the node ones act only in pathedit mode).

### Tool options bar (`#tool_options_panel`)

Shown while the mode's tool has `options()`. A tool registering `options()` / `setOption(id, value)` (`core/tool-registry.js`) gets this tray with no markup. In tablet mode the same controls fill `#ts_tool_options` (a pill under the command bar); `refreshToolOptions` fills every tray that exists. `panels/toolOptionsBar.ts` draws one control per descriptor (`number` → `se-spin-input`, `select` → `se-select`, `checkbox`), sends changes to `svgCanvas.setToolOption`, then reads `options()` again (a descriptor may be `hidden` depending on another). It refreshes on `modeChange` and from `updateContextPanel`; descriptor labels are already translated.

### Path node editing tools (`.path_node_panel`, pathedit mode)

A transient mode toolbar, so it stays in the top bar.

| ID | Control |
|----|---------|
| `tool_node_link` | Link / unlink control points |
| `seg_type` | Segment type: Straight (4) / Curve (6) |
| `tool_node_smooth` | Smooth node: one-shot (`pathActions.smoothSelectedNodes()` → `Path#smoothSelectedNodes()`, `core/path-method.js`) that makes each selected node's in / out handles collinear (G1) from the neighbour-anchor tangent construction **without moving any anchor**. Unlike `tool_smooth_path` (a lossy paper.js re-fit, freehand only) it keeps node-authored geometry; it moves only handles on curve (type 6) sides, and a side next to a straight segment or with no neighbour is untouched |
| `tool_node_clone` | Clone node |
| `tool_node_delete` | Delete node: **reconnects** its neighbours and keeps the shape (below); also Backspace / Delete in pathedit |
| `tool_node_average` | Average selected nodes (ext-path-edit; `se-select` menu Horizontal / Vertical / Both → `averageSelectedNodes('h'\|'v'\|'both')`; needs ≥ 2 nodes) |
| `tool_node_add_anchors` | Add a node at the middle of every segment, shape kept (ext-path-edit, `addAnchorPoints()`) |
| `tool_openclose_path` | Toggle open / closed |
| `tool_add_subpath` | Add sub-path |

**Click targets.** Only the node and handle **grips** change the selection. Clicking the path's own stroke is inert (it does not marquee, reselect a neighbour or exit edit mode), because the stroke runs under the handles and a near-miss must not steal the selection (the `#downOnPath` guard in `core/path-actions.js`). Empty canvas still exits to select mode; a marquee from empty canvas still multi-selects nodes.

**Grips.** Anchor nodes are **squares** (`NODE_GRIP_SIZE = 9`), bézier handles smaller **circles** (`r: 3`), so overlapping ones can be told apart. Handles show **only for the selected node(s)**: node `i` owns its incoming handle (`c2`) and the next segment's outgoing one (`c1`); `Path#refreshCtrlPtDisplay()` decides visibility from the selection (`core/path-method.js`: `addPointGrip`, `addCtrlGrip`, `Segment#showCtrlPt`).

**Node alignment while dragging.** Dragging an anchor grip (not a handle) detects x / y alignment with another anchor of the *same* path within ~8 screen px and shows a guide line and ring through the smart-guides overlay (`core/path-node-guides.js`). It is informational: the node keeps following the raw cursor, since nodes are too small a target to fight a hard snap. Governed by `tool_smart_snap`; drag only, not while placing points.

**Delete node (reconnect, shape kept).** The button and Backspace / Delete (the `delete_selected` hotkey in `Editor.ts`, guarded by `getMode() === 'pathedit'` and `pathActions.canDeleteNodes`) call `pathActions.deletePathNode()` → `buildReconnectedPathData(path)` (`core/path-actions.js`). The path is read into the anchor model (`segsToSubpaths`, `core/path-edit.js`; `M` and the closing segment fold into one start anchor, so a closed path's start vertex can go too) and each deleted node goes through `removeAnchor`: neighbours keep their handle directions and the facing handles are **refitted** (`core/bezier-fit.js`: least squares with fixed tangents, golden-section search for where the new curve passes the old node) so one cubic follows the two old segments; two straight segments become one; removing an end of an open path drops its segment. Several nodes are removed highest index first. A closed shape stays closed (reduced to two straight nodes it becomes an open line). The refit costs ~40 least-squares fits per node: fine for a click, never call it from a mousemove. The output `d` is absolute `M/L/C` with an explicit closing lineto plus `Z`. Splitting a shape open is the **cutter's** job (`ext-cutter`), not delete-node's.

**Mobile mode** (`MainMenu.clickMobileMode`, `uiMode: 'mobile'`): for viewing drawings and rough sketching on a phone. `.svg_editor` carries `ui-mobile`; `mobile.css` hides the desktop panels and shows `MobileShell` (`panels/MobileShell.ts`). The view state shows the menu top-left, a zoom pill (− % + fit) top-right and an **Edit** button. **Edit** (`mobile_edit_toggle`) lifts view only and shows a bottom bar: **Pan · Pencil · Text** (tool lock on, so the tool stays armed), a colour chip that opens a palette of seven colours and three stroke widths (the defaults for new strokes and texts; a colour also recolours the text being edited), **Undo / Redo** and **Done** (back to viewing). The shell checks every press before the canvas sees it (capture `mousedown` on `#workarea`) and resets the canvas to the state's tool when it has drifted to another mode (Select after a text edit, the double-click and Space shortcuts); the context menu is suppressed. Leaving mobile mode restores the tool lock and Select. No Select, eraser, shapes or layers, by design: undo is the way to fix a stroke. Tests: `mobile-shell.spec.js`.

**Export region (frames).** The export dialog (`dialogs/exportDialog.ts`) has `#se-export-region` (`<se-select>`), rebuilt on open from the canvas's `[data-frame]` rects: "Whole canvas" (value `""`) plus one entry per frame (by `<title>`), pre-selecting the selected frame; the chosen `frameId` rides on the dialog's `change` detail. `MainMenu.clickExport` turns it into a `{x,y,w,h}` crop (the frame's attributes, `getBBox()` as fallback) via `resolveFrameCrop(frameId)` and passes `crop` to `rasterExport`. In `core/svg-exec.js` the export **always strips `[data-frame]` elements** from the clone (frames never appear in an image); with a crop it narrows the clone's `viewBox` and sets an explicit `width` / `height` (Firefox needs them to rasterize an `<img>`). It also calls `embedUsedFonts(clone)`, because the `<img>` cannot see the document's fonts (see Fonts below). `File → Save` keeps frames.

### ext-shape-family — Spiral, Arc, Rectangular Grid, Polar Grid (`extensions/ext-shape-family/`)

### ext-connector — Line-binding engine (`extensions/ext-connector/`)
No button or mode of its own: it is the binding engine behind the core **Line tool**, which draws the `<line>` while the extension binds it.
- **Model**, on the `<line>`: `se:bind-start` / `se:bind-end` = element id (attribute absent = free endpoint). The bbox cache (`start_bb` / `end_bb`) is in the `DataStorage` WeakMap. A bound end sits at the shape-edge intersection (`getBBintersect`) of the line aimed at the other end, offset outward for a marker (`getOffset`); `routeLineBinding(line)` does it, `routeAny` dispatches line → it and polyline → `routeConnector`.
- **Draw flow:** `mouseDown` records the shape under the press; `mouseMove` highlights the end target; `mouseUp` reads `opts.element` (added to the core mouseUp payload in `event.js`) and, unless **Alt** is held, binds each endpoint that landed on a shape and routes. It returns `undefined`, so core keeps or culls the line as usual.
- **Tracking:** `findConnectors` / `updateConnectors` re-route bound lines when their element moves, driven by `elementTransition`, `selectedChanged`, `elementChanged` and the overridden `moveSelectedElements`.
- **Hover:** one overlay (`#se_conn_hover` with N/S/E/W snap dots), shown by a `#workarea` mousemove listener when `mode === 'line'` and idle.
- **Legacy:** `<polyline se:connector="startId endId">` connectors (straight / elbow via `routeConnector` / `computeConnectorPoints`, `se:conn_mode`) are still recognised (`getBindIds`, `reset`, `IDsUpdated`) and keep tracking; there is no UI to make new ones. The `conn_` id prefix is reserved for them (`[id^="conn_"]`); the overlay uses `se_conn_`.

### ext-grid — Grid Settings (`extensions/ext-grid/`)
`grid_settings` (`<se-grid-settings>`) popover: show-grid and snap toggles, shape, colour, step. Shapes: `square` (a canvas → PNG `<pattern>` tile, zoom-adjusted), `isometric`, `triangle`, `perspective1`, `perspective2` (`<line>`s in `#gridLines` over the canvas extent, redrawn on zoom and resize by `svgEditor.updateGrid`), plus the composition guides. Settings persist as `grid_*` prefs (`ConfigObj.seedGridConfigFromPrefs`).

### ext-markers — Line Markers (`extensions/ext-markers/`)
Adds the **Markers** section (`#marker_panel`) to the Design tab after Stroke & Opacity (falls back to `#tools_top`), with three `se-list` pickers (Start / Mid / End) for one selected line / polyline / path / polygon; its visibility is self-managed in `selectedChanged` (`showPanel`).
- Options: None, Left / Right Arrow, Triangle, Diamond, Open Arrow (V), Box, Circle, Star, X, Forward / Reverse / Vertical Slash. Filled shapes also have open `_o` variants; open-stroke types (`openarrow`, slashes, `xmark`) are forced `fill:none` (`strokeOnly`) so SVG doesn't auto-close them. Geometry is the `markerTypes` map (100×100 box, forward = +x); each type needs an icon `images/<id>.svg`.
- **Head position** (`#marker_align`, `se-select`; `core/arrow-align.js`): picking a start / end marker is one undo step (`transact('Set marker')`) that also sets `se:arrow-align="tip"` on an element without one; the picker changes it (`transact('Head position')`). *Tip* moves each marker's `refX` to the head's tip and trims the stroke by the head's inset; *Extend* puts the tip an inset past the end; *Centered* is `refX=50`. Heads with no tip (box, circle, star, slashes, X) stay centred. `elementChanged` re-syncs (`svgCanvas.syncArrowAlign`) after stroke-width, marker or colour changes; `ext-connector` writes the real ends (`getArrowSourcePoints` / `setArrowSourcePoints`) and keeps an aligned head's own offset (`getArrowOffset`: 0 for Tip, the inset for Extend).

### ext-shaper — Shaper (`extensions/ext-shaper/`)
`tool_shaper` (mode `shaper`, Shift+N, right after the pencil): draw a rough shape. On release `core/shape-recognize.js` (DOM-free, port of VectorCraft `recognize.rs`) classifies the stroke and replaces it with a native element in the current paint: line → `<line>` (free angle kept), rectangle → `<rect>`, ellipse → `<ellipse>`, regular polygon (3–8 sides) → `<polygon>`. Near-squares and near-circles snap to equal sides (within 10 %); rectangles and ellipses snap to 45° steps (a `rotate(a cx cy)` transform when ≠ 0); a triangle points up or down, a hexagon sits flat or pointy.
- A **scribble** (a zig-zag with several sharp reversals) **deletes** what it touches: children of the current layer / group whose painted fill or stroke a sample of the scribble lands on (`isPointInFill` / `isPointInStroke`, only for paint the element has, so a scribble inside an unfilled outline leaves it; groups recurse; text and images use their bbox; frames are skipped), through `deleteSelectedElements` so mirror twins and text-on-path behave as for Delete. A scribble that touches nothing is cancelled.
- Anything else is **discarded**: no path, no undo step. The tool stays active after a discard or scribble and returns to Select after a created shape (tool lock keeps it). One undo step per stroke (`registerTool`, "Shape stroke"); the live ink is a `<polyline>` in the tool overlay (`vector-effect: non-scaling-stroke`), never saved. In the tablet More tools flyout.

### ext-cutter — Knife/Cut Tool (`extensions/ext-cutter/`)
`tool_cutter` cuts the selected shapes (all shapes if nothing is selected). A **drag** is an instant straight cut. A **click** without movement starts a zig-zag: click adds vertices, **Enter** or double-click cuts along the polyline, **Backspace / Delete** drops the last vertex, **Escape** cancels. **Shift** snaps a segment to the nearest 15° from its start (`snapToAngle`, `core/math.ts`). `cutShapes(points)` in `core/cutter.js` handles 2 points and 3+ alike with an exact boundary splice (`getIntersections` / `divideAt`) that takes any even number `2m` of crossings per loop (a Weiler-Atherton-style stack decomposition) and yields `m + 1` pieces (an S-cut that dips in and out twice makes 3). A compound path with several disjoint loops is cut loop by loop; a loop the cut doesn't cross is untouched.

### ext-curvature — Curvature Tool (`extensions/ext-curvature/`)
`tool_curvature` (Y): click to place anchors; curves are auto-computed by **Spiro** (clothoid, the `spiro` package), its only smoothing mode. **Shift+click** = a sharp corner. **Alt+click** = an **end** anchor: the curve up to it is fixed, and it also starts the next segment (Alt rather than Ctrl, because Ctrl+click is a secondary click on macOS and some Linux setups). Only `corner` / `end` are stored per point, are independent (**Alt+Shift+click** = an end anchor that is also a corner), and "start" / "mid" are derived. `buildPathD` splits the points into independent segments at each `end` anchor (`splitIntoSegments`) before `buildSpiro` / `buildCatmullRom`; with no `end` anchor it is the single global solve. Dragging a placed anchor reshapes its adjoining segments for the rest of the session (nothing about anchors persists after finalising). Double-click (or clicking near the start) finalises and closes; switching tools mid-session finalises the path open (a `modeChange` listener calls the same `finalize(false)`), leaving no preview dots behind. **Escape** also finalises it open.

### ext-puppet-warp — Puppet Warp Tool (`extensions/ext-puppet-warp/`)
`tool_puppet_warp` (X, mode `puppetwarp`): Illustrator-style mesh deformation. Select an object (or a **group**) and enter the tool; its geometry at entry is the session's **rest pose**. Click empty canvas to drop a **pin**, **drag** a pin to bend the shape around the pins left fixed. Switching tools **commits** the pose as one undo step; **Escape cancels** (rest geometry back, no undo entry). Only `path` / `rect` / `circle` / `ellipse` / `line` / `polyline` / `polygon` are warpable (`WARPABLE`); `text`, `image` and `use` inside a warped group stay put (said in the tooltip).
- **Math** (`mls.ts`, pure; `tests/unit/ext-puppet-warp-mls.test.js`): Moving Least Squares *rigid* deformation (Schaefer et al., SIGGRAPH 2006): each point gets a rigid (rotation + translation, no shear) transform weighted by inverse distance to the pins; `deformPoint(v, pins, alpha)` reproduces a global rigid transform exactly.
- **Pipeline** (`ext-puppet-warp.ts`): on entry primitives are `convertToPath`'d, selection grips cleared (they would eat drags), and each path resampled by paper.js into dense **content-space** polylines at uniform **arc-length** steps (~6 units), because paper's `flatten` splits only curved spans and would leave a straight limb as two unbendable points. Element-local `d` maps to content space with `matrixMultiply(getMatrixToContent(el), getMatrix(el))`: the element's **own** transform *and* its ancestors' (`getMatrixToContent` alone drops the path's own `transform` and warps in the wrong frame). Each drag re-warps from the cached rest and rewrites `d` as a dense polyline; **commit** refits it to cubics with `svgCanvas.simplifyPathD(d, 2)`, so the baked path stays compact across re-pose sessions. Pins are `<circle>`s in the current layer (`pointer-events: none`, `var(--accent)` for the dragged one), removed on exit.
- **Undo:** the whole session (conversion, warp, rig attributes) runs inside ONE `svgCanvas.beginTransaction('Puppet Warp', { onAbort })` held from entry to exit: commit is one undo step, Escape cancels it, and `onAbort` ends the session when undo or a file load interrupts it. A held transaction swallows the undo steps of anything else that runs meanwhile (`techdebt.md`).
- **Persistence:** a single-shape selection (one shape, or a group with exactly one warpable descendant) keeps its rest pose and pins as `se:puppet-rest-d` / `se:puppet-pins` (the `se:orig-d` idiom of `core/corner-radius.js`) and re-hydrates on re-entry; `svgCanvas.registerGeometryRemap` keeps them in step with baked moves and scales (an extension cannot import `geometry-remap-registry.js` itself: that resolves to a source copy disjoint from the one `coords.js` ships). Multi-shape selections stay session-only (the remap hook fires for `<path>`, not `<g>`).
- **Escape** is a `window` *capture* keydown listener guarded on mode, not the extension `keyDown` hook: that hook runs from a bubbling document listener, after the hotkey dispatcher may already have switched tools on Escape, which would commit the pose instead of cancelling it.

### ext-smart-guides — Smart Alignment Guides (`extensions/ext-smart-guides/`)
No mode or tool of its own; the companion of the object-to-object snapping in the `event.js` select-move branch (`core/smart-guides.js`: `collectSnapTargets` once per drag, `snapMovingBBox`, `findEqualSpacing`; all on **stroked / visual** bboxes; tolerance 8 screen px). Implements `svgCanvas.showSmartGuides(payload)`: solid accent lines spanning the moving box and the matched target, dashed equal-spacing segments with end ticks, in `<svg id="smartGuides">` appended **last** in `svgroot` (above content; position synced from `#svgcontent` per draw, cleared on mouse-up by core). Toggle `tool_smart_snap`, config `smartSnapping`, pref `smart_snapping` (default on). Skipped while a group context is active (child bboxes aren't content-space); the page edges and centre are a synthetic target, so centring snaps on an empty page.

### ext-corner-radius — Corner Rounding (`extensions/ext-corner-radius/`)
Adds the **Corner style** section (`#corner_panel`: `corner_radius_value` + `corner_kind_r/i/c`) to `#tab_design` before Object (see the Design tab table for when it shows; never in pathedit). `svgCanvas.applyCornerRadius(r)` (`core/corner-radius.js`) swaps a polygon / polyline for a `<path>` in the same batch and turns every straight-corner vertex into an `A` arc fillet with per-corner trim clamping (`min(r/tan(θ/2), len/2, len/2)`), one `BatchCommand` per edit. Model: `se:corner-radius` + `se:orig-d` (the canonical absolute M/L/Z source; `se:` attributes bypass sanitize, so they survive save and load); radius 0 restores the source and removes both. `coords.js` `remapElement` calls `remapCornerSource`, so baked moves, scales and flips regenerate `d` from the source (no stale-geometry teleport). If `d` is rewritten outside the pipeline (node edits…), the extension sees the mismatch on selection and silently drops the rounding attributes, leaving the shape.

### ext-repeat — Radial / Grid Repeat (`extensions/ext-repeat/`)
`<se-repeat-settings>` popover from `tool_repeat` (Object, after the offset popover) and `tool_repeat_multi` (Combine). **Radial** (copies 1–36, sweep°, centre = canvas / own / **custom**), **Grid** (rows, cols, gap X / Y) or **Path** (see the Combine row).
- `svgCanvas.repeatSelection(params)` clones the selection once per step: radial prepends `rotate(angle cx cy)` (never recomputed, since baking would decompose the rotates), grid prepends `translate(j·stepX, i·stepY)` with step = stroked bbox + gap. Clones get fresh ids (`remapElementIdsAndRefs`; defs and paint servers stay shared); one `BatchCommand('Repeat')`. `[data-frame]` rects are never repeated.
- **Custom centre:** `center: 'custom'` + `centerX` / `centerY`, set by clicking the canvas, never typed: *Pick center* calls `svgCanvas.armRepeatCenterPick(cb)`, arming the one-shot mode `'repeat-pick-center'` (in `EditorStartup.ts`'s `modesToCancel` and crosshair-cursor switch); the extension's `mouseDown` hook (guarded on that mode) takes the next click, returns to select and calls back. The source is **never moved**: its existing distance from the chosen centre becomes every copy's radius (draw one petal off-centre, pick the flower's centre, fan copies around it).
- **Re-editable:** the source carries `se:repeat-source="<uid>"` + params in `se:repeat`; copies carry `se:repeat-copy="<uid>"`. Reopening the popover (source **or any copy** selected) pre-fills via `svgCanvas.getRepeatParams()`; Apply → Update deletes the copies by uid and regenerates in the same batch. Copies are plain elements, so files render identically anywhere.

### ext-segment — Segment / Shape Divide (`extensions/ext-segment/`)
`<se-segment-settings>` popover from `tool_segment` (Object, after `tool_repeat`): **Radial** (lines 2–72, start angle°) or **Grid** (lines 1–72, vertical / horizontal), and a Split / Non-split toggle. No centre picker: radial divides around the shape's own centre (`resolveCenter` in `core/segment.js`: `cx` / `cy` of an untransformed circle or ellipse, else the bbox centre). `svgCanvas.segmentSelection(params)`: **split** makes N (radial) or N+1 (grid) independent `<path>`s, each `shapePath.intersect(wedgeOrStripPolygon)` in paper.js (one polygon per piece rather than one N-way divide, which is more robust); **non-split** draws the N lines on top, clipped exactly to the true outline with `getIntersections()`, and wraps shape + lines in a new `<g>`. One `BatchCommand` either way. Non-split is re-editable (the `<g>` carries `se:segment="radial;count=…;split=0;…"`; `getSegmentParams()` seeds the popover for the `<g>` or the wrapped shape); switching it to Split first removes the old lines and unwraps the shape. Offered when `svgCanvas.canSegment(elem)`: one element other than `text` / `tspan` / `image` / `use` / `symbol` / `g` / `defs`; no multi-selection or group input.

### ext-mirror — Mirror Drawing (`extensions/ext-mirror/`)
The mode is **API-only** (`svgCanvas.setMirrorAxis('v'|'h'|null)` / `getMirrorAxis()`; no button). A dashed accent axis (`#mirrorAxis` on `#canvasBackground`, redrawn on zoom and resolution change) shows while it is set. Each freshly drawn element gets a reflected twin: the extension **wraps `svgCanvas.addCommandToHistory`** and replaces a bare `InsertElementCommand` of a layer child (the hand-drawn commit) with one `BatchCommand('Draw mirrored')` holding source and twin, so one Ctrl+Z removes both. Batched inserts (paste, repeat, booleans), `[data-frame]`, group-context drawing and its own twins pass through. A twin is a clone with `translate(w 0) scale(-1 1)` (or the horizontal analogue) prepended and `se:mirror-of="<sourceId>"`; `<text>` is position-mirrored only (glyphs stay readable); twins stay live-linked to their source (`extensions.md`). **Mirror-copy selection** (`tool_mirror_copy` / `_multi`): `svgCanvas.mirrorSelection()` reflects a copy across the canvas axis (vertical when the mode is off) as one batch.

### ext-shadow — Drop Shadow (`extensions/ext-shadow/`)
A "Shadow" section (`#shadow_panel`) for any single selected element: an **On** switch (`shadow_enabled`), **Angle** (`shadow_angle`, 0–359°, clockwise from 12 o'clock; 90° = 3 o'clock, 180° = straight down), **Distance** (`shadow_length`, 0–500 px; `length` internally), **Blur** (`shadow_blur`), **Opacity** (`shadow_opacity`, shown 0–100, stored 0–1), **Color** (`shadow_color`). Angle + distance are the UI form; internally they become `dx` / `dy` on `feDropShadow`, and files with raw `dx` / `dy` load and display correctly. **Length 0 ⟺ no shadow** in the data model: turning the switch off removes the shadow, turning it on (or editing any field while off) applies it with a default distance of 8. `svgEditor.shadowApi = { read(elem), apply(elem, params, batchCmd) }` works on an explicit element (unlike the panel's `setShadow`, which targets the selection); the `<se-class-select>` save popover shows a **shadow** checklist row, stores `shadow: {angle,length,blur,opacity,color}` on the preset and re-stamps it on apply in the class's undo batch. ### ext-outline — Outline / Halo (`extensions/ext-outline/`)
An "Outline" section (`#outline_panel`, right after `#shadow_panel`) giving a line a second colour around its own stroke (a white line with a black halo). **Line family only:** `line`, `polyline`, `path`, `polygon`. **Width** (`outline_width`, 0–50 px; **0 ⟺ no outline**), **Opacity** (`outline_opacity`, 0–1), **Color** (`outline_color`), **Remove** (`outline_remove`). Built as `feMorphology(dilate, radius=width)` → `feFlood(color)` → `feComposite(in)` → `feMerge[outline, SourceGraphic]`; dilate makes mildly boxy corners at large widths (negligible on thin lines). `svgEditor.outlineApi = { read, apply }` backs an **outline** checklist row in the class save popover (`outline: {width,color,opacity}`).

### ext-glow — Outer / Inner Glow (`extensions/ext-glow/`)
A "Glow" section (`#glow_panel`, after `#outline_panel`) for any single element, text included. An **outer** group (Blur, Opacity %, colour), an **inner** group (the same plus `glow_inner_source`: *Edge* = inward from the edge, *Centre* = outward from the middle) and a **Feather** group (`glow_feather_radius`: fades the object's own edges inward, and the outline, glows and shadow follow the soft edge). **Blur 0 = no glow** (that group is dimmed, `data-off`). Defaults: blur 5, opacity 75 %, outer `#ffff00`, inner `#ffffff`. It owns only the glow and feather slices of the shared composer spec, so a shadow or outline is preserved; one undo step per edit; `getBlur()` ignores composer-owned filters (`data-fx` / `_fx` / `_shadow`), so a glow's blur never reads as the element's Blur. `svgEditor.glowApi` (`read` / `apply`) lets class presets capture `preset.glow = {outer, inner, feather}`.

### Filter coexistence (ext-shadow + ext-outline + ext-glow)
An element's `filter` attribute references only one `<filter>`, so the effects compose into ONE (`{id}_fx`, or a legacy `{id}_shadow` reused in place) via `fx-filter.ts` and stay independently editable (the shadow is cast by the shape plus its glow). A pre-existing *foreign* filter (a blur) is saved and restored when all effects are removed, so an effect still cannot coexist with blur. `feMorphology` / `feMerge` need `result` in the `sanitize.js` whitelist to survive save and load.

### ext-fonts — Custom Fonts (`extensions/ext-fonts/`)
Adds the `<se-font-library>` button (`tool_font_library`) beside the font-family select: a Google Fonts browser popover (search + category chips) over a bundled static catalog (`google-fonts-catalog.json`, ~1,934 families from `fonts.google.com/metadata/fonts`), so browsing needs no network. Names preview in their own face: as rows scroll in, an `IntersectionObserver` injects a `text=`-subsetted Google Fonts `<link>` (a few KB) into `document.head`; offline, names stay in the UI font until downloaded. Picking a font: `fontStore.ensureFont()` fetches the WOFF2 once through the CSS2 API, stores it in IndexedDB (`svgedit-fonts`), registers it with `document.fonts` and the canvas registry (`svgCanvas.setEncodableFont`), and works offline from then on; on startup `restoreAll()` re-registers every cached font and re-adds it to `tool_font_family`. `fontStore.ts` is imported **only** by `seFontLibrary.ts` (one bundled instance); `ext-fonts.ts` is DOM-only and reaches it through the element's `restoreCachedFonts()`.
- **Embed-on-export:** `embedUsedFonts(svgRoot)` (`core/svg-exec.js`) injects a `<style>` with one base64 `@font-face` per *used* font into the passed root's `<defs>` (created if missing). Family names are **unquoted** and there is no `format()`, so the payload has no XML-special characters and survives serialization. Unused fonts are not embedded. Callers: the SVG-string path (`svgCanvasToString`) embeds into the *live* doc, gated on `getSvgOptionApply()`, and removes the `<style>` right after serializing; `rasterExport` embeds unconditionally into its *clone*, because the `<img>` cannot see `document.fonts`.

## Keyboard shortcuts

Every command's id, label and default keys are in [`commands.md`](commands.md), generated from the command registry (the authority for keys; the tables above no longer repeat them). Typing-time keys are not commands: **Shift+Enter** inserts a new row in the text being edited and **Enter** commits it and leaves edit mode.

**Paste sources.** Paste is one native `paste` listener (`EditorStartup.ts`), not the `v` shortcut. It accepts svgedit's own internal clipboard (pasted via `pasteInCenter`) and an external **SVG document** from another app (e.g. Excalidraw's "Copy as SVG"), which is imported through `importSvgString` and then `ungroupSelectedElement`ed into a real, editable group (otherwise it lands as one opaque `<use>`). See "System-clipboard paste" in `architecture.md`.

## Colour picker (`se-colorpicker` → `se-color-dialog`)

Clicking the Fill / Stroke / Background swatch opens `<se-color-dialog>` as a **popover** anchored to it (`dialog.anchor`, set by `seColorPicker.openColorDialog()`): no backdrop, no Apply / Cancel footer, no built-in preset grid (the bottom palette is beside it). Solid, gradient, group (leaf shapes, as `setColor` does) and canvas-background tweaks preview live and write no history; **a click outside commits** (one undo step, old → new), **Escape cancels** and reverts, an untouched click-away changes nothing, and clicking the swatch again commits. Without an on-screen anchor (the tablet shell, command search, a hidden swatch) it stays the centred modal, as does the palette's swatch editor. Its screen eyedropper hides the dialog and calls `svgCanvas.suspendContextDimming()` so group-context dimming doesn't distort the sampled pixels. Layout: `:host(.popover)` in `ColorDialog.css.js`.

## Canvas page commands

`canvasCommands.ts` registers size, background and layout as commands with typed params (`canvas_set_size`, `canvas_set_background`, `canvas_apply_layout`, `canvas_save_layout`, `canvas_delete_layout`; saving over an existing name is the overwrite). The Canvas Settings popover (`seCanvasSettings.ts`) and the bottom panel's solid background colour run them through `commands.tryRun(id, params, source)`, so they appear as `action` entries in the debug log. Gradient backgrounds still call `editor.setBackground(…, true)` directly (a gradient element is not a command param). A `ParamSpec.values` may be a function, read on every `list()` and validation.
